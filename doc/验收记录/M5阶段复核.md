## 已确认问题与处理顺序

1. **M5-R01：共享 RAG 批量来源登记 SQL（已修复）。** [MessageSourceMapper](../../backend/support-ai-data/src/main/java/com/haha/supportai/data/conversation/mapper/MessageSourceMapper.java) 的 `insertAll` 用 `UNION ALL` 合并多条来源，原先 `ticket_id`、`tool_call_id` 使用无显式类型的 `NULL`，PostgreSQL 报 `column "ticket_id" is of type uuid but expression is of type text`。该问题延续 M3-R01，影响多来源登记、越界批次拒绝和 RAG 历史继承。现已将两列改为 `CAST(NULL AS UUID)`，保留全部授权校验，相关 Mapper 数据库测试 6/6 通过。
2. **M5-R02：缺少真实质量依据。** 四份状态文件和实际绑定目录检查均未提供可复核的真实运行结果。来源登记已修复；下一步补齐模型环境，按同一提交、环境、60 题开发集生成 VECTOR、FUSION、FUSION+RERANK 结果，人工核对收益/退化与费用、时延；之后才做单因素调整和默认配置冻结。
3. **M5-R03：可交付基线尚未统一。** 对 `cf3802e` 做静态核对可见两个 V12 迁移，且该提交的 `RagProperties` 缺少已被 `RagEvidenceSelector` 调用的证据预算及阈值字段。当前工作区已有相关未提交修复，因此工作区编译和迁移通过不能证明纯提交可交付；本轮未另外检出纯提交构建。应将既有修复整理为可审查基线后，再独立检出验证。
4. **跨阶段 M6-R01：安全/接口测试装配与文档回归（已修复）。** 初次因历史仓储缺少测试替代依赖导致 13 项测试无法启动。补齐后复现并修复旧 OpenAPI 兼容问题，以及上传表单文档和分组断言问题；两个测试类现已 13/13 通过，见 M6 修复补记。

本轮已修正 [评测说明](../../evaluation/README.md) 中“F18/F19 尚未实现”和过期的环境描述。F18/F19 已有实现，但 M4 的真实版本切换、删除/撤权和失败恢复验收仍待完成；旧状态 JSON 保持原记录时间，作为历史证据保留。
