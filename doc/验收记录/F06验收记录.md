## 已交付范围

| 范围 | 交付内容 |
| --- | --- |
| 任务查询 | `GET /api/ingestion-jobs/{jobId}`，Controller 统一位于 bootstrap 的 `controller.knowledge`，使用 OpenAPI 3.0 注解 |
| 查询授权 | 按 jobId、当前用户和知识库成员关系查询；越权、不存在、停用知识库和无成员统一按任务不存在处理，避免泄露其他知识库任务 |
| 脱敏回执 | 返回状态、阶段、attempt、进度、可重试/可取消标识和白名单错误；不返回内部错误详情、堆栈、SQL、文件路径或供应商信息 |
| 可靠领取 | 使用 `FOR UPDATE SKIP LOCKED` 原子领取；领取同时递增当前阶段 attempt、生成 owner/token、设置租约有效期并清理旧错误，阶段推进后 attempt 归零 |
| 租约隔离 | 心跳、进度、阶段推进和失败记录必须同时匹配 owner、token 和未过期条件；旧 Worker 不能覆盖新 Worker 的任务状态 |
| 执行边界 | 有界 `ThreadPoolTaskExecutor` 预留轮询和任务执行；领取与状态写入使用短事务，后续解析、分块和模型调用必须在事务外 |
| 前端状态 | 上传后查询任务状态，展示排队、运行阶段、等待重试、失败和完成；状态查询失败保留可重试入口，并避免并发轮询 |

F06 只建立可靠任务基础设施和查询回执。F07 才接入解析/分块处理器，F08 才负责 Embedding、向量写入以及 READY、active、pending 和任务成功状态的原子发布；在后续处理器和发布事务完成前，F06 不得单独把任务标为 `SUCCEEDED`。

## 关键状态与顺序

```text
F05 上传
  -> ingestion_job = QUEUED / PARSE
  -> 按阶段和 next_run_at 原子领取
  -> attempt + 1，写入 owner/token/lease_until
  -> 事务外执行阶段处理
  -> 续租或写入进度（仍需 owner + token + 有效期）
  -> 阶段完成后释放租约并排入下一阶段
  -> F08 完整发布事务完成后才允许 SUCCEEDED
```

执行器关闭或应用重启不会删除任务记录；启用 Worker 并注册对应阶段处理器后，到期租约可被下一次领取回收。F06 交付时 Worker 只注册 `PARSE`、`CHUNK`，当前 F08 已注册 `EMBED`、`PUBLISH`；各阶段是否实际可完成仍须分别执行数据库和模型验收，不能把停留状态当作成功。

## 待执行命令

```powershell
mvn -f backend/pom.xml -DskipTests clean compile
mvn -f backend/pom.xml clean test
mvn -f backend/pom.xml -Pdb-it verify
npm --prefix frontend run test -- --run
```
