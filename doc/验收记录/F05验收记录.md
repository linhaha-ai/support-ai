## 已交付范围

| 范围 | 交付内容 |
| --- | --- |
| 数据结构 | Flyway V6 创建 `document`、`document_version`、`ingestion_job`，包含状态、正数、哈希、1024 维、唯一性、索引及中文表列注释 |
| 版本边界 | `active_version_id`、`pending_version_id` 通过 `(document_id, version_id)` 复合外键约束，不能指向其他文档版本 |
| 数据访问 | MyBatis-Plus PO、枚举、Mapper、Repository；JSON 配置快照显式转换为 PostgreSQL JSONB，不在业务层使用 JdbcTemplate |
| 文件存储 | `FileStore` 与 `LocalFileStore` 使用服务端随机键、临时文件和同卷原子移动；删除幂等并拒绝非法存储键 |
| 上传用例 | `POST /api/knowledge-bases/{kbId}/documents` 接受 UTF-8 Markdown/TXT，限制扩展名、MIME、大小、文件名和展示名，返回 202、Location 及三类标识 |
| 权限一致性 | 落盘前执行 WRITE 校验；数据库短事务内锁定启用知识库和成员关系后再次校验 WRITE，使上传登记与撤权/改权串行化 |
| 事务补偿 | 文件先完整落盘，再创建文档、首版、QUEUED/PARSE 任务并设置 pending；数据库事务失败时删除文件 |
| 配置快照 | 固化解析器、分块器、当前 Embedding 提供方/模型和 1024 维配置，不记录 API Key；保存 SHA-256 配置摘要 |
| 前端 | WRITE 知识库展示上传区，READ 不展示；FormData 不手工指定 Content-Type，复用 CSRF，提交期间防重复，成功后只显示“已接收，处理中” |
| OpenAPI | 上传接口包含 operationId、Cookie 鉴权、CSRF、multipart 文件/展示名、202 回执模型；未添加重复 `@ApiResponses` |

F05 只负责接收原文件并建立持久任务，不执行解析、分块、Embedding 或版本发布。任务领取与查询属于 F06，解析属于 F07，向量写入和 `active_version_id` 切换属于 F08；因此首次上传成功后 `active_version_id` 必须为空，不能宣称文档已经可以问答。

## 关键状态与顺序

```text
校验 KB-W、文件大小/类型/UTF-8
  -> FileStore 以随机 key 完整落盘
  -> 短事务锁定 knowledge_base + kb_member
  -> 再次确认 WRITE
  -> document(active=NULL, pending=NULL, next=2)
  -> document_version(version=1, status=QUEUED)
  -> ingestion_job(status=QUEUED, stage=PARSE)
  -> document.pending_version_id=versionId
  -> 提交并返回 202
```

任一数据库步骤失败时整个事务回滚，外层删除已经写入的 `storage_key`。补偿删除失败只记录内部键、追踪标识和异常类型，不把文件内容、真实路径、数据库详情或凭据返回客户端。
