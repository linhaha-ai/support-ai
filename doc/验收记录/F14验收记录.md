## 本阶段实现

- 开放 `GET /api/chat/runs/{runId}`，只允许当前启用账号查询本人未删除会话中的运行。
- 状态响应返回 run、会话和成对消息标识，运行/助手状态，部分或完整回答，当前授权来源，模型用量、执行指标、脱敏终态错误及时间信息。
- 查询正文前重新校验会话固定知识范围；任一知识库已停用或成员权限失效时，保留可取消能力，但不返回回答正文和来源。
- 只返回最终答案实际引用、且当前仍能通过分块来源接口鉴权的来源；无法确认权限时隐藏来源，不使用生成时快照降级。
- 开放 `POST /api/chat/runs/{runId}/cancel`，继续使用 Sa-Token Cookie 与 CSRF 请求头；撤销知识库权限后，会话拥有者仍可停止自己的活跃运行。
- 取消事务先锁定本人 run，再将 QUEUED/RUNNING 条件更新为 CANCELLED，保存 `cancel_requested_at`、固定错误码和脱敏说明，同时将助手消息由 STREAMING 更新为 CANCELLED，保留已生成正文。
- 取消事务提交后才从进程内执行登记表移除任务、请求中断并推送取消终态；没有本机任务登记时，数据库取消结果仍然有效。
- 完成、失败、取消和总超时均先条件更新 run，再更新助手消息或引用；四种路径只允许一个终态胜出，已完成运行不会被取消或超时覆盖。
- 每个新任务被执行器接受时安排独立的 180 秒总超时，排队时间同样计入。超时先将 run/助手消息条件更新为 FAILED / `MODEL_TIMEOUT`，再中断任务；运行线程发现超时终态后沿用相同稳定错误码，不能抢先发出普通模型错误。
- RAG 执行发现 run 已取消时直接结束取消分支，不再把中断改写为模型失败或持久化失败。
- 应用启动时以启动边界为条件，将此前遗留的 QUEUED/RUNNING 运行与对应 STREAMING 助手消息原子收口为 FAILED / `RUN_INTERRUPTED`，不重新提交模型调用。
- 前端收到 start 后绑定 run，提供带确认提示的停止按钮；停止时先关闭本地显示流，再调用取消接口并以 GET 查询到的数据库终态覆盖页面。后端返回 `cancellable=false` 时不显示无效停止入口，取消请求失败后保留错误并在状态未知时恢复重试能力。
- SSE 非主动断开后自动查询已保存状态；运行仍活跃时展示后台处理中和刷新入口。断流后的首次查询也失败时保留 active run、状态未知提示和手动刷新，不把它误判为已结束；活跃运行或请求发送期间禁止新建会话而丢失运行控制。幂等 JSON 复用也立即查询 run，不重放 SSE 或再次调用模型。
- V1.0.0 继续不实现 Last-Event-ID；F15 的会话列表、历史消息、重命名和删除未提前实现。

## 终态与中断顺序

```text
取消请求校验当前账号和 run 归属
-> 锁定 run
-> 条件更新 run 为 CANCELLED 并保存 cancel_requested_at
-> 更新助手消息为 CANCELLED，保留部分正文
-> 提交事务
-> 从执行登记表移除并请求中断模型任务
-> 连接仍可写时发送 RUN_CANCELLED error 并结束 SSE
```

完成、失败和总超时同样先争夺 run 条件更新。取消或超时未赢得竞争时保留实际 COMPLETED、FAILED 或 CANCELLED 状态，不修改已有终态。浏览器展示和 SSE 事件不是权威状态，断线、刷新和竞争后均以 GET run 的持久化结果为准。

## 待执行验收

按项目规则，本轮没有擅自运行 Maven、Docker、Flyway、Testcontainers、真实模型、真实后端 API 或浏览器场景。建议用户执行：

```powershell
mvn -f backend/pom.xml -DskipTests clean compile

mvn -f backend/pom.xml -Pdb-it verify
```

随后启动 PostgreSQL 与 Ollama，准备 READY active 知识数据，至少验证：

1. 新运行和已完成运行只能由会话拥有者查询，其他用户统一得到 404，响应不泄露会话或来源信息。
2. 生成中能查询已保存部分正文；断开 SSE 后后台继续生成，GET 最终得到 COMPLETED、FAILED 或 CANCELLED 的真实状态。
3. 点击停止后先看到数据库 CANCELLED，再结束模型任务；助手消息保留部分正文且不再追加。
4. 完成与取消同时发生时只有一个终态，COMPLETED 不会回退为 CANCELLED，CANCELLED 不会被后续失败覆盖。
5. 撤销知识库权限后，GET 不返回正文和来源，但会话拥有者仍能取消活跃运行。
6. 引用来源在查询时再次鉴权；已撤权、已停用、旧 active 版本或不存在的 chunk 不出现在 sources。
7. 应用进程中断并重启后，旧 QUEUED/RUNNING 变为 FAILED / `RUN_INTERRUPTED`，对应助手消息变为 FAILED，且模型调用次数不增加。
8. 相同请求键相同载荷返回原 run 并立即查询状态，不再次生成；相同键不同载荷仍返回 409。
9. Ollama 与 DashScope 各完成一次生成中取消、断流后查询和正常完成竞争场景。
10. 运行排队或生成超过 180 秒时只保存 FAILED / `MODEL_TIMEOUT`，SSE 只出现同一错误码；正常完成、用户取消与超时同时竞争时仍只有一个数据库终态。
