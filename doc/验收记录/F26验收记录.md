# F26 验收记录：受控只读工具与调用证据

日期：2026-09-23

结论：**F26 的两个受控只读工具、服务端可信上下文、工具调用审计、工单/文档来源映射和会话范围授权已经实现，并通过单元、安全上下文及隔离 PostgreSQL 验证；由于 F25 前置任务尚未通过完整验收，且当前开发数据卷尚未升级到 V13，F26 保持未勾选。**

## 本阶段实现

- 新增 Flyway V13 `tool_call` 表，记录 run 内调用序号、白名单工具名、对象参数、受限结果快照、状态、稳定错误码和起止时间，并为表和全部字段提供中文数据库注释。
- 将 `message_source` 扩展为 DOCUMENT/TICKET 两种形态：知识工具来源关联 chunk 与本次 tool_call，工单来源关联 ticket 与本次 tool_call；普通 RAG 文档来源继续允许不关联工具调用。
- 新增 `AssistantToolContext`，仅由服务端已准备的 run、session、user 和助手消息构造。模型参数 DTO 只包含 `query` 或 `ticketNo`，不能指定用户、会话、SQL、文件路径、模型端点或任意工具名。
- 新增 `searchKnowledge(query)` 适配器。它复用现有授权检索链路和固定会话范围，固定 TopK 为 5，只返回证据正文与服务端生成的 `sourceHandle`，不在工具内部生成答案。
- 新增 `getTicketStatus(ticketNo)` 适配器。它要求工单知识库同时属于 ASSISTANT 会话固定范围和用户当前可读范围，每次直接查询业务表，不复用旧工单状态。
- 工具开始、成功和失败分别使用独立短事务。开始时锁定助手消息并分配 run 内连续调用序号；成功时先保存受限结果，再在同一事务逐项复核真实来源并写入 `message_source`；失败时只保存稳定错误码，不落未经授权的结果。
- `searchKnowledge` 与 `getTicketStatus` 是服务端固定白名单，持久化层再次核对工具类型、run、会话、用户、助手消息、知识库成员关系及真实 chunk/ticket 归属。伪造用户、工具名、跨调用来源或不存在来源均无法写入。
- 现有授权检索 SQL 已允许 RAG 和 ASSISTANT 两种会话模式，仍在排序和 TopK 前执行固定会话范围、实时成员权、ACTIVE 知识库、当前 READY 版本及索引配置过滤。

## 场景核对

| 场景 | 结果 |
| --- | --- |
| 知识工具正常检索 | 仅返回授权证据与服务端来源句柄，并登记 DOCUMENT 来源 |
| 工单工具正常查询 | 返回数据库当前状态，登记 SUCCEEDED 调用与对应 TICKET 来源 |
| 同一 run 连续两次查询 | `call_no` 为 1、2，引用编号连续；状态更新后第二次返回新值 |
| 参数格式错误 | 调用记录为 FAILED，错误码为 `INVALID_REQUEST`，不登记来源 |
| 工单不存在 | 调用记录为 FAILED，错误码为 `RESOURCE_NOT_FOUND`，不泄漏额外信息 |
| 用户在库中有成员权，但库不在本会话范围 | 与工单不存在相同，不登记来源 |
| ASSISTANT 会话知识检索 | 仅返回固定会话范围内、当前仍授权的 active READY 文档 |
| 伪造用户或工具名 | 在登记调用前拒绝，不产生审计行 |
| 伪造 ticket/tool_call 来源关系 | 成功状态与来源写入事务整体回滚，工具调用仍可转为 FAILED |
