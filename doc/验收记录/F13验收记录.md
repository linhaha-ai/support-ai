## 本阶段实现

- 开放 `POST /api/chat/sessions/{sessionId}/messages`，请求只接受 `clientRequestId` 与 `content`，继续使用 Sa-Token Cookie 和 CSRF 请求头。
- 流前同步完成参数、身份、会话归属、固定知识库范围、幂等和单活跃 run 校验；错误继续返回统一 JSON，不建立伪 SSE 错误流。
- 新请求返回 `text/event-stream`，并设置禁止缓存和禁止代理缓冲；相同幂等键与相同载荷返回已有 run 的 JSON，不重新调用模型，相同键不同载荷返回冲突。
- 增加独立有界执行器，默认并发数 4、队列容量 32、SSE 超时 200 秒；队列满时将已准备的 run 收口为 FAILED，并返回流前 429 `REQUEST_LIMITED`。
- 准备结果携带服务端确认的 userId，异步检索、证据复核和来源展示不依赖请求线程的 Sa-Token 上下文。
- Spring AI `ChatClient.stream()` 输出被转换为项目自己的 start/delta/sources/done/error 事件，不暴露框架内部事件。
- run 先由 QUEUED 条件更新为 RUNNING，再发送 start；每个非空模型增量先按 run、消息和 STREAMING 状态原子追加到助手消息，再发送 delta。
- 生成完成后先提交 COMPLETED，再在 sources 实际发送前按当前 userId 立即复核引用来源；只有仍可读取的来源进入 sources，复核异常时失败关闭为空列表，来源点击仍通过 `GET /api/chunks/{chunkId}/source` 再次鉴权。
- 助手正文、合法引用、usage、metrics 和 COMPLETED 在短事务中提交成功后，才发送 sources 和 done；模型未返回 usage 时数据库和事件均保存为 `null`，不伪造零值。
- 模型、检索或持久化失败时保留已经持久化的部分正文，保存脱敏错误、已知 usage 和 metrics，并只发送 error；供应商异常原文不会进入事件或业务错误字段。
- SSE 写入失败或客户端断开只停止继续发送，不隐式取消后台生成；run 查询、主动取消和重启恢复仍属于 F14。
- Vue 使用 fetch、ReadableStream 和 TextDecoder 消费 POST SSE，支持跨网络块、CRLF 与中文分片；页面逐步追加答案、保留失败前正文，并通过来源抽屉加载授权正文。
- 前端严格校验已知事件顺序，done 前必须已收到 sources；未知事件被忽略，为后续受控 tool 事件保留兼容性。

## 事件与持久化顺序

```text
同步准备并提交 QUEUED run 与成对消息
-> 有界执行器领取
-> 提交 RUNNING
-> start
-> 授权检索、二次复核并提交全部入模来源
-> ChatClient 流式生成
-> 每个 delta：先追加数据库，再发送事件
-> 提交完整正文、引用、usage、metrics 和 COMPLETED
-> sources 发送前立即再次复核可展示来源
-> sources
-> done
```

任一步进入失败分支时，以条件更新保存 FAILED 和当前部分正文，再发送 error。SSE 只是实时展示通道，数据库终态仍是最终事实来源。
