## 本阶段实现

- 新增 `POST /api/ingestion-jobs/{jobId}/retry` 与 `POST /api/ingestion-jobs/{jobId}/cancel`，沿用 Sa-Token Cookie 和 CSRF 请求头，并补充 OpenAPI 3 注解。
- 查询与操作均使用当前登录用户；READ 成员只能查看任务，WRITE 成员才会获得操作标记并通过服务端原子条件再次校验权限。
- 人工重试只接受 `FAILED`、未达到 `max_attempts`、未请求取消、版本仍为 `FAILED`、没有其他 pending 且没有更高 active 版本的任务。
- 人工重试保留 `attempt`、阶段、进度和既有幂等批次数据，只恢复版本状态、重新取得 `pending_version_id` 并将任务置为 `QUEUED`；下次领取时再递增 attempt。
- 取消只接受 `QUEUED`、`RUNNING`、`RETRY_WAIT`，在同一条数据修改 CTE 中终止任务和版本、清空租约并仅释放本版本的 pending 指针；重复取消返回已有终态。
- 自动重试继续保留 pending；终止失败、重试耗尽和取消均同步版本终态并清理匹配的 pending，避免失败版本阻塞后续上传。
- 任务领取、重试等待和写入租约复核均要求版本仍可执行且仍持有 pending；取消后旧 Worker 无法续租、推进、写入或重新领取。
- 解析空内容、无效配置、分块超限和索引不完整改为不可自动重试；文件读取、向量服务和未知处理异常继续按上限进入 `RETRY_WAIT`。
- 任务响应新增脱敏的 `errorStage`，并区分“阶段失败，等待自动重试”和“阶段终止失败”。
- 文档管理页为 WRITE 成员提供重新处理与取消按钮，取消前二次确认；动作成功后同步版本状态、pending 指针和文档修订号，失败时保留当前页面并显示可恢复提示。

## 原子状态转换

```text
自动失败且可重试
RUNNING -> RETRY_WAIT，保留 pending 和版本构建态

终止失败或重试耗尽
RUNNING -> FAILED，版本 -> FAILED，仅清理匹配 pending

人工重试
FAILED -> QUEUED，版本 -> QUEUED/BUILDING，重新取得 pending，保留 attempt

取消
QUEUED/RUNNING/RETRY_WAIT -> CANCELLED，版本 -> CANCELLED，租约失效，仅清理匹配 pending
```
