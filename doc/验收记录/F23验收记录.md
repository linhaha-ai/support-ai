# F23 验收记录：可关闭的重排序与失败回退

日期：2026-09-23

结论：**F23 的独立 qwen3-rerank 适配、授权候选重排、输入边界、失败回退、指标追溯和同集比较工具已实现并通过定向自动化验证；同一开发集的真实开启/关闭对比尚未执行，因此 F23 保持未勾选，重排序默认保持关闭。**

## 本阶段实现

- 在 `support-ai-ai` 中新增独立 `RerankModelAdapter`，按阿里云百炼 qwen3-rerank 兼容接口的扁平请求和下标响应进行调用，不启用 Spring AI Alibaba 旧版 rerank 自动配置。
- 密钥继续只读取 `SPRING_AI_DASHSCOPE_API_KEY`；完整 HTTPS 地址由 `SUPPORT_AI_RERANK_ENDPOINT` 注入，配置快照不记录地址或密钥。开启时若模型、地址、密钥或超时配置无效，应用在模型 Bean 创建前失败。
- 请求只包含统一授权仓储已经返回的候选正文。模型只返回输入下标和相关性分数，服务端按稳定下标映射回原 `chunkId`，不能引入新候选或改变来源标识；问答在登记来源和进入 Chat 模型前仍执行既有二次授权校验。
- 默认候选倍数为 3、单次最多 50 条、单条保守估算最多 3500 Token、单次保守估算最多 100000 Token、超时 5 秒；查询、排序指令和候选正文共同计入请求预算。官方文档明确 qwen3-rerank 单次最多 500 条、单条最多 4000 Token，并给出总量计算口径；项目另以 120000 Token 作为可配置总量硬上限。
- 没有候选或只有一条候选时不调用模型；输入超限、模型不可用或响应缺失、重复下标、越界下标、非法分数、顺序异常时返回原基础排序。基础策略为 `FUSION` 时回退到 RRF 顺序；当前默认策略仍是尚待 F22 实测的 `VECTOR`。
- 新增未到达、`DISABLED`、无候选、候选不足、输入超限、已应用、不可用回退和异常响应回退状态。检索调试响应与 `chat_run.metrics` 记录状态、候选数、阶段耗时和已知 Token，OpenAPI Schema 已同步；`rerankMs` 是 `retrievalMs` 内的子阶段，不能重复相加。
- `chat_run.config_snapshot` 升级为 `f23-v1`，记录开关、提供方、模型、候选和 Token 上限、超时及排序指令，不记录连接地址或密钥。
- 评测脚本新增 `compare-rerank` 命令，只允许同一 development 数据集、Git 提交、环境和除开关外完全相同的配置；输出质量变化、收益/回退题、Chat 与重排序 Token、状态分布及 P50/P95 耗时差值。未调用重排序明确计为 0 Token，已调用但提供方未返回用量时保留 `null`。

qwen3-rerank 的接口形态与硬上限依据[阿里云百炼文本排序模型 API 参考](https://help.aliyun.com/zh/model-studio/text-rerank-api)实现；当前仓库使用更保守的默认限制。

## 已知阻塞与待验收

- F23 依赖 F22；F22 尚未完成同一开发集的 VECTOR/FUSION 真实比较，当前基础检索策略仍保持 `VECTOR`。
- 尚未上传并绑定演示语料的实际 `documentId/versionId/chunkId`，也未配置可调用的 qwen3-rerank 工作空间地址和密钥。
- 尚未获得开启/关闭两组的真实质量、回退题、重排序 Token、调用费用和耗时，不能据此开启默认配置。
- 认证后的 OpenAPI JSON 仍受既有 Knife4j 与 SpringDoc 版本不兼容基线影响；本阶段只执行检索接口定向契约复核。

## 完成判定

只有 F22 的基础策略可用，并在同一 60 题开发集上完成重排序关闭/开启双跑、人工核对收益与回退、记录真实用量和耗时且确认权限边界后，才可勾选 F23。当前结论是“重排序独立能力、回退保护与比较工具实现完成，真实质量验收待前置和环境”。
