## 本阶段实现

- `POST /api/chat/sessions` 允许创建固定知识库范围的 `ASSISTANT` 会话；运行准备结果携带服务端确认的会话模式，RAG 与助手共用幂等、单活跃 run 和配置快照。
- 引入 `spring-ai-alibaba-agent-framework`，使用 `ReactAgent` 固定注册 `searchKnowledge`、`getTicketStatus` 两个本地只读回调，不接受用户或模型动态增加工具。
- 默认限制每轮最多 2 次工具调用、3 次模型调用、单次 8000 Token 上下文、16 次图递归、20 秒单工具超时和 60 秒总执行时间；配置快照保存本轮非敏感预算与工具清单。
- 工具执行过程映射为项目 `tool` SSE，只发送工具名和 `STARTED/SUCCEEDED/FAILED` 状态，不发送调用参数、结果正文或隐藏推理。
- 模型只能输出服务端已登记的 `[[source:UUID]]` 来源句柄。服务端拒绝未知句柄、残留句柄和模型自行生成的数字引用，再转换为既有 `[n]` 引用和 DOCUMENT/TICKET 来源响应。
- 查询当前工单状态时，本轮必须实际调用 `getTicketStatus`；未调用、工具失败或来源引用不可信时写入稳定失败终态，不补造业务结果。
- ASSISTANT 继续复用现有消息提交、运行查询、主动取消、超时中断、断流后台完成和来源权限复核；RAG 会话仍走原 `RagAnswerService` 路径。
- 前端增加 RAG/智能助手模式选择、tool 状态展示和工单来源展示；文档来源仍通过授权预览接口打开，工单来源不伪造文档预览链接。
- OpenAPI 会话与消息描述已同步两种模式和 `tool` 事件。

## 场景核对

| 场景 | 当前验证结果 |
| --- | --- |
| 创建 ASSISTANT 会话 | 服务端保存所选模式，前端发送并解析 ASSISTANT |
| 知识/工单工具白名单 | ReactAgent 仅装配两个固定回调，前端也只接受两个固定名称 |
| 工具、模型、上下文超限 | 本地预算抛出稳定错误码并进入 FAILED，不继续执行 |
| 当前工单未实时查询 | 服务端拒绝回答并记录 `AGENT_REQUIRED_TOOL_NOT_CALLED` |
| 模型伪造 `[n]` 或来源句柄 | 引用解析失败，不生成来源映射 |
| 工具过程展示 | SSE 顺序允许 start 后发送 tool，sources/done 仍保持唯一终态协议 |
| RAG 模式回归 | 仍调用原 RAG 服务，既有流式测试通过 |
| 取消与总超时 | 复用运行登记和中断机制；ASSISTANT 总时限使用独立 60 秒配置 |
