## 判定范围

M7 要求从空环境演示完整业务、恢复后重复关键流程，并展示各任务结果。F32 进一步要求 F01—F31 的验收均有可复现结果，35 个业务操作和16 张业务/向量表关系得到覆盖，逐题核对固定集依据、引用和拒答；不能仅凭 HTTP 200 宣布通过。

人工质量要求来自 F21 的人工核对规则；自动汇总或本次 Codex 复核不能替代签核。云端不是 M7 顶层额外增加的要求，但 F01 完成条件包含两种提供方；F23 要求同一开发集真实关闭/开启重排序比较，F24 要保留三策略可比结果。因此本轮不能因默认使用 Ollama/VECTOR 就默默缩小完整验收范围。

固定题标准没有要求零质量缺陷。已记录的回答缺漏和题目预期冲突应由正式质量评审判断影响；它们不自动等于权限泄漏或数据安全缺陷，也不能通过改写固定题或填写虚构人审分数消除。

## 复现入口

后端在 JDK 21 与现有 Maven 环境执行下列两批；`db-it` 默认匹配 DatabaseIT，历史升级兼容单独指定，避免遗漏。各次实际计数以新生成报告为准，不扫入旧报告。

```powershell
mvn -f backend/pom.xml -Dmaven.repo.local=E:/mvnrepository -Pdb-it verify
mvn -f backend/pom.xml -Dmaven.repo.local=E:/mvnrepository -Pdb-it -Dtest=NoSuchTest -Dsurefire.failIfNoSpecifiedTests=false -Dit.test=FlywayMigrationCompatibilityIT -Dfailsafe.failIfNoSpecifiedTests=false verify
npm.cmd --prefix frontend test -- --run
npm.cmd --prefix frontend run build
npm.cmd --prefix evaluation test
npm.cmd --prefix evaluation run validate
```

真实旧引用生命周期脚本为 [verify-m7-lifecycle.ps1](../../deploy/scripts/verify-m7-lifecycle.ps1)，凭据经 `SUPPORTAI_F32_ADMIN_PASSWORD` / `SUPPORTAI_F32_READER_PASSWORD` 注入。它只创建并操作本轮专属夹具，删除仅针对自身新建文档；保留会话、来源元数据和失败记录。使用新的 `-OutputPath`，已有记录拒绝覆盖。

无头浏览器脚本为 [verify-m7-browser.mjs](../../deploy/scripts/verify-m7-browser.mjs)，通过 `M7_BROWSER_USERNAME` / `M7_BROWSER_PASSWORD` 提供账号，`M7_PLAYWRIGHT_MODULE` / `M7_BROWSER_EXECUTABLE` 指向已有 Playwright 与 Edge。使用独立上下文，不操作用户打开的浏览器，不保存 Cookie 或登录页截图；每次提供新的 `--output` 路径。两个脚本使用同一演示账号时应串行执行，避免新登录使旧会话失效。

本轮不新增产品范围、不替用户豁免验收要求，也不将配置缺失描述为模型服务已失败。原 `AGENTS.md` 的本地修改保留，不纳入本次提交。
