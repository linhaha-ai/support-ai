# F29 验收记录：跨功能授权与数据一致性回归

日期：2026-09-24

结论：**F29 开发与自动化验收已完成。后端普通测试 361/361、13 组真实 PostgreSQL 场景 58/58、前端完整测试 95/95 和生产构建全部通过。跨功能场景已覆盖两个普通用户、无成员权管理员、会话拥有者、WRITE/READ 变化、撤权和知识库停用；前端在权限刷新失败后不再保留缓存原文或分块。M7 仍需继续完成 F30—F32。**

## 实现范围

- 新增 `CrossFeatureAuthorizationDatabaseIT`，以真实上传受理、数据库发布状态、授权检索、会话运行、来源登记和只读工单工具组成一条跨模块链路。
- 同一场景使用两个普通用户和一个无知识库成员权的管理员。另一个普通用户只能读取自己的工单；跨用户资源标识、会话标识、运行标识和工具上下文均不能读取目标用户内容。
- 实时调整成员权限：WRITE 时可上传、读取和写检索；降为 READ 后仍可读取正文、分块、来源、会话、运行和工单，但不能上传、删除、取消任务或使用写检索。
- 撤销成员关系后，文档、任务、正文、分块、来源、检索和工单入口均不可读；会话拥有者仍能看到会话结构，但消息正文、回答和来源立即隐藏。
- 恢复成员后再停用知识库，验证直接入口、检索、历史消息和运行结果继续按停用状态隐藏内容。
- `useDocuments` 在当前所选版本的原文或分块刷新失败时，立即清空对应缓存和分块游标，避免权限变化后继续显示旧的敏感正文。
- 修复 `DocumentVectorDatabaseIT` 的版本夹具参数数量错误，并关闭该类不相关的后台清理调度，确保向量约束回归稳定执行。
- 保留已发布的 V12 工单和 V13 工具迁移及其校验值，将冲突的文档清理迁移顺延为 V14；新增 V13→V14 前向升级测试，不使用 `repair` 改写历史。
- 复用既有版本切换、删除、Worker 租约恢复、授权检索、三轮来源失效、工具审计和 Flyway 兼容测试；不为验收绕过生产服务授权逻辑。

## 场景矩阵

| 场景 | 验证结果 |
| --- | --- |
| WRITE 成员贯穿访问 | 上传、任务、原文、分块、来源、读写检索、会话、run、工单和工具均可按授权访问 |
| 第二个普通用户 | 可读取自己的工单；不能读取另一用户文档、任务、检索结果、会话、run 或借用其工具上下文 |
| 无成员权管理员 | 管理角色不自动获得知识库正文、工单、会话、run、来源和工具调用权限 |
| WRITE 降为 READ | 读取链路保留；上传、删除、任务取消和写检索被拒绝 |
| 撤销成员关系 | 直接资源入口统一不可读；本人会话结构保留，但正文、回答和来源清空 |
| 知识库停用 | 即使恢复成员关系，文档、检索、工单和会话内容仍不再暴露 |
| 资源标识隔离 | 文档、版本、任务、分块、会话、run 和工具上下文均不能通过替换标识跨主体读取 |
| 版本、删除与 Worker | 既有数据库场景验证条件更新、唯一约束、版本切换、删除和租约失效后不能重新发布 |
| 三轮失效来源 | 助手历史回归验证文档或工单来源失效后，不再进入后续模型上下文 |
| 前端受限刷新 | 原文返回 403、分块返回 404 后，缓存正文、分块和后续游标立即清空并显示错误 |
| 迁移兼容 | 隔离库从 V1 执行到 V14，并验证已有 V13 数据库可向前升级到 V14 |

## 回归中发现并修复的问题

首次扩大数据库回归中，`DocumentVectorDatabaseIT` 的 `document_version` 插入 SQL 有 6 个占位符但传入 7 个参数，导致该类 6 个场景在夹具初始化阶段报错。移除多余参数并关闭测试上下文中的后台文档清理调度后，该类 6/6 通过，随后完整 13 类回归 58/58 通过。

前端此前只记录刷新失败，不会清除已加载的原文和分块。权限被撤销、知识库停用或资源失效时，页面可能继续显示旧缓存。本次在确认失败请求仍对应当前选择后清空缓存，避免旧请求影响已切换的新版本。
