## 实现范围

- 新增 `DELETE /api/documents/{documentId}`，仅当前 ACTIVE 知识库的 WRITE 成员可调用，携带 CSRF，成功返回 202；READ、撤权或不可见文档统一不可发现。
- 删除事务锁定 document 行。首次删除设置 `deleted_at`、清空 active/pending、revision 加 1，取消全部非终态导入、清空旧 Worker 的 owner/token/lease，并取消 QUEUED/BUILDING 版本。
- 重复删除保持幂等：不重复增加 revision、不重复修改终态版本，并通过 `UNIQUE(document_id)` 只登记一条清理任务。
- V14 新增 `document_cleanup_job`，提供 PENDING、RUNNING、RETRY_WAIT、SUCCEEDED 状态、领取次数、到期时间、租约 owner/token、脱敏错误和自动重试时间。
- 清理器以独立单线程调度领取已删除文档的任务。它先幂等删除该文档全部版本的受控文件，再在短事务中复核当前未过期租约，删除该文档分块对应的向量正文并提交成功。
- 清理失败只允许当前未过期租约写入 RETRY_WAIT；旧 Worker、过期租约或被重新领取后的令牌不能完成或改写任务。
- `document`、`document_version`、`document_chunk` 和 `message_source` 保留，满足历史证据定位；清理不影响其他文档和其文件、向量。
- 导入领取新增未删除文档及当前 pending 条件；既有分块、向量和发布事务继续复核文档行、pending 和有效租约，删除与写入/发布竞争后不能复活文档。
- 新检索、来源预览和多轮历史注入不再使用已删除资料。已有回答在当前知识库授权仍有效时保留来源元数据，但返回 `available=false`、`isCurrent=false`、`previewPath=null`，且不返回正文；撤权、账号停用或知识库停用仍完全隐藏。
- 文档详情页只向 WRITE 用户显示删除图标与二次确认；成功后清空详情并重新加载文档列表，失败时保留当前详情和明确错误。

## 关键状态流

```text
WRITE 用户确认删除
  → 锁定 document 并复核账号、知识库和成员权限
  → 首次删除：deleted_at + 清 active/pending + revision 加 1
  → 取消非终态 ingestion_job 并撤销租约
  → 取消 QUEUED/BUILDING document_version
  → 幂等登记 document_cleanup_job
  → 202，文档立即退出检索、预览和历史注入
  → 清理器领取有效租约
  → 幂等删除目标文档全部受控原文件
  → 短事务复核未过期租约并删除目标 vector_store
  → SUCCEEDED；失败则脱敏 RETRY_WAIT
```

## 自动化测试契约

后端测试已经覆盖或声明以下场景，只有实际运行后才能计为通过：

| 场景 | 预期结果 |
| --- | --- |
| WRITE 首次删除 | 202；deleted_at 非空，active/pending 为空，revision 只加 1 |
| 导入失效 | RUNNING 任务转 CANCELLED，取消时间存在，owner/token/lease 清空，旧租约不能写回 |
| 防止重新领取 | 已删除文档的 pending 任务不能再被任一导入阶段领取 |
| READ 删除 | 404 `DOCUMENT_NOT_FOUND`，文档与清理任务不变 |
| 重复删除 | 两次均返回 202，revision 不再递增，只有一条清理任务 |
| 目标隔离 | 只删除目标文档的文件和向量，其他文档数据保持不变 |
| 历史定位 | 目标文档的版本、chunk、message_source 继续存在 |
| 原链接失效 | 删除后来源预览返回 404，不能读取旧正文 |
| 历史来源展示 | 回答正文仍可见，来源为 unavailable/current=false/null path，响应不含来源正文 |
| 清理租约 | owner/token 匹配但已过期时，重试写回返回 false，状态和 token 不变 |
| 清理失败 | 保存稳定错误码与脱敏原因，进入 RETRY_WAIT，不记录文件路径或异常原文 |
| OpenAPI | DELETE operationId、Cookie 鉴权、CSRF header 和 202 响应存在 |
