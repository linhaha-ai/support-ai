# F30 验收记录：失败诊断、资源限制与用户反馈

日期：2026-09-29

结论：**F30 开发与自动化验收已完成。后端普通测试 78 个报告、368/368 通过；19 类真实 PostgreSQL Testcontainers 场景 84/84 通过；前端 11 个文件 95/95 通过，生产构建通过。自动化场景覆盖 traceId 持久与异步恢复、模型不可用、数据库异常脱敏、健康状态 DOWN、队列满、单用户并发超限、未知模型用量及取消/超时终态。未调用真实外部模型，也未执行浏览器人工场景。**

## 实现范围

- 新增 V15 前向迁移，为 `chat_run`、`ingestion_job` 增加可空 `trace_id`，同时增加长度/非空白约束、条件索引和中文列注释；不修改已执行的 V12—V14 迁移。
- 创建问答运行或入库任务时保存当前请求 traceId；流式问答执行、问答超时、入库阶段处理和租约心跳在异步线程恢复同一 MDC 上下文，结束后恢复线程原上下文。
- 运行与任务状态 OpenAPI 模型返回可空 traceId，兼容 V15 之前的历史数据；前端在失败/取消时展示追踪号，普通 HTTP 错误从 `X-Trace-Id` 读取追踪号。
- 将问题字符上限和单用户跨会话活跃运行上限纳入 `support.ai.chat.stream` 配置。默认问题上限 2000 字符、单用户最多 2 个活跃运行；账号行锁串行化同一用户配额判断，第三个运行返回 429 `REQUEST_LIMITED`。
- 保留既有上传 5 MB、导入/流式有界执行器、问答执行超时、助手工具/模型调用次数、上下文 Token 与总执行时间限制，并在 README 汇总当前边界。
- 前端将模型用量收敛为明确类型；供应商未返回用量时显示“模型 Token 用量未知”，已返回时分别显示输入、输出和合计 Token。
- 通用异常仅返回稳定 `INTERNAL_ERROR`、用户提示和 traceId；DOWN 健康响应只公开总体状态，不返回 JDBC、密码或组件细节。

## 场景矩阵

| 场景 | 验证结果 |
| --- | --- |
| 问答 traceId | 请求 traceId 写入 `chat_run`，运行状态接口返回相同值，流式工作线程和超时线程恢复对应 MDC |
| 入库 traceId | 上传请求头、数据库 `ingestion_job.trace_id`、任务状态响应保持一致，Worker 阶段和心跳恢复对应 MDC |
| 历史数据兼容 | V14 数据库前向升级到 V15；新增列可空，旧运行和任务仍可读取 |
| 单用户并发 | 同一账号通过账号行锁串行判断，默认允许 2 个跨会话活跃运行，第 3 个请求返回结构化 429 |
| 队列容量 | 流式执行器拒绝任务时返回稳定限流结果，未启动的运行不会无限等待 |
| 模型不可用 | 模型异常进入脱敏 FAILED 终态；已开始的流式运行在失败、取消或超时竞争后只保留一个可解释终态 |
| 数据库不可用 | 通用 SQL 异常响应不包含连接字符串或密码；健康状态 DOWN 时不公开内部组件详情 |
| 未知模型用量 | 后端接受供应商未返回 Token，SSE/状态解析兼容空用量，页面明确显示“未知” |
| 前端失败反馈 | 会话、文档和知识库任务显示稳定错误提示；有 traceId 时同时显示追踪号 |
| 既有资源预算 | 文件大小、导入/流式执行器、问答超时、助手工具/模型调用和上下文预算继续由显式配置控制 |
