## 本阶段实现

- data 新增 `AuthorizedRetrievalHit`、`AuthorizedRetrievalMapper` 和 `AuthorizedRetrievalRepository`。
- knowledge 新增检索请求/响应、显式异常和 `KnowledgeRetrievalService`。
- bootstrap 新增 `POST /api/knowledge-bases/{kbId}/retrieval-tests`，要求 Sa-Token 登录态、CSRF 和目标知识库 WRITE 权限。
- 请求仅接受 `query` 与 `topK`，其中 query 去除首尾空白后长度为 1—2000，topK 范围为 1—50；未知的用户、知识库范围、SQL 或自由过滤字段明确拒绝。
- 查询向量由当前唯一 `EmbeddingModel` 生成一次。默认 Ollama 使用 query 用途，DashScope 由现有模型边界写入 `textType=query`，并统一校验 1024 维和有限数值。
- 为后续会话问答保留会话范围检索方法；调用方只传入 `sessionId`，Repository 联合会话和范围表校验会话归属、未删除、RAG 模式，并与当前用户仍有效的成员关系求交集。

## 授权与检索顺序

正式查询通过一条关系 SQL 联合以下条件，完成过滤后才执行 pgvector 精确余弦排序和 `LIMIT topK`：

1. 当前账号存在且启用。
2. 当前账号仍是知识库成员；调试入口额外要求 `permission=WRITE`。
3. 知识库处于 `ACTIVE`。
4. 文档未逻辑删除。
5. `document.active_version_id` 指向当前版本，且版本状态为 `READY`。
6. 版本列、配置快照和实际 pgvector 均属于当前 provider/model/1024 维空间。
7. 会话属于当前用户、未删除且模式为 RAG；命中的知识库必须位于服务端保存的会话固定范围内。

因此无权但相似度更高的向量不会先占满全局 TopK，也不会通过 Java 层事后过滤造成有权结果遗漏。F11 不新增数据库迁移或 HNSW 索引，先保留精确查询基线。

## 待执行验收

按项目规则，本轮没有擅自运行 Maven。需要在 Docker、PostgreSQL 和模型环境就绪后执行：

```powershell
mvn -f backend/pom.xml -DskipTests clean compile
mvn -f backend/pom.xml clean test
mvn -f backend/pom.xml -Pdb-it verify
```

随后启动 Ollama 并准备 `bge-m3`，使用 WRITE、READ、库外和停用账号分别调用真实接口，确认：

- WRITE 请求返回 200，结果只含本库已发布 active 版本，并返回分数和耗时。
- READ 请求返回 403；库外用户、无成员管理员和停用账号不能获得证据。
- 无有效候选时返回 200 和空 `matches`，而不是 `null` 或内部错误。
- 附带 `userId`、`kbIds`、`filter` 或 `sql` 等未知字段时返回 400。
- 切换 Ollama/DashScope 或模型名称后，旧空间向量不参与检索，重建后才恢复命中。
