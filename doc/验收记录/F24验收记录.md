# F24 验收记录：固定检索与回答配置并核对质量取舍

日期：2026-09-23

结论：**F24 的证据预算、分策略阈值、完整配置快照、索引配置隔离、三策略统一报告和单因素比较工具已实现并通过定向自动化验证；真实开发集调参和默认策略选择尚未执行，因此 F24 保持未勾选，继续使用 `VECTOR` 且关闭重排序。**

## 本阶段实现

- 在二次授权复核后、来源登记和 Chat 调用前增加证据选择器。证据先按实际最终排序类型使用向量、RRF 融合或重排序阈值过滤，再按既有顺序截取满足 CL100K 正文 Token 预算的前缀；预算不会让低排名证据越过高排名证据。
- 新增 `max-evidence-tokens`、`minimum-vector-score`、`minimum-fusion-score` 和 `minimum-rerank-score` 配置。真实开发集尚未运行前，默认值分别为 4096、-1.0、0.0 和 0.0，不预设未经验证的质量阈值。
- `chat_run.metrics` 新增授权复核后证据数、分数过滤数、预算过滤数、实际入模正文 Token 和 Embedding Token 用量。计数满足“筛选前 = 入模 + 分数过滤 + 预算过滤”；当前 Embedding 提供方没有可用用量字段时明确保存 `null`，不伪装为 0。
- `chat_run.config_snapshot` 升级为 `f24-v1`，明确记录 Chat、Embedding、Rerank 三种角色及实际模型，同时记录回答预算、三类阈值、提示词版本和当前 parser/chunker/Embedding 索引配置哈希，不写入地址或密钥。
- 五条授权向量、关键词和二次复核 SQL 均增加 `document_version.config_hash` 条件。查询时使用当前完整文档处理快照哈希，因此分块、解析或 Embedding 配置改变后，旧版本索引不会被当作新配置检索；必须重新导入并发布匹配配置的版本。
- 评测运行契约同步为 `f24-v1`。校验器会核对模型角色、查询与索引 Embedding 一致性、索引哈希、回答配置、证据计数守恒、Token 预算和未知用量表达。
- 新增 `compare-strategies`，统一报告 `VECTOR`、`FUSION`、`FUSION + RERANK` 三组的质量、退化题、用量与耗时；三组必须来自相同 development 数据集、Git 提交和环境，除策略与重排序开关外配置完全一致。
- 新增 `compare-factor`，只允许 TopK、证据预算、单个策略阈值、分块、Embedding 或提示词中的一个明确因素变化。分块或 Embedding 变化必须同时产生新索引配置哈希，其他运行配置必须继续使用同一索引；除代码内提示词外使用同一 Git 提交，提示词比较则必须人工确认两个提交只修改提示词及其版本。
- 固定测试集保持未参与调参。`evaluation/results/f24-tuning-status.json` 将真实执行数记录为 0，没有生成或推断质量、Token、费用和耗时收益。
