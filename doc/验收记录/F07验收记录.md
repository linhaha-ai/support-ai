## 一、范围与结论

F07 负责把已上传的 Markdown/TXT 原文件转换为带章节和原文位置的分块元数据，并将处理结果推进到 `EMBED` 阶段。F07 不负责生成 Embedding、不写入 `vector_store` 正文或向量、不将文档版本切换为 `READY`、不切换 `active_version_id`，因此本阶段完成代码不代表资料已经可以问答。

本阶段已实现的代码能力包括：

- 通过受控 `FileStore.open(storage_key)` 读取原文件，不拼接用户文件名或暴露真实磁盘路径。
- 校验文件大小、读取字节数、SHA-256 摘要和严格 UTF-8 解码；失败使用脱敏的处理错误码。
- 清理 BOM、CRLF/CR 换行、行尾空白和不支持的 C0 控制字符；清洗后为空时返回 `DOCUMENT_EMPTY`。
- 使用 CommonMark 解析 Markdown 标题，保留完整标题层级；TXT 使用空标题层级。
- 使用 `CL100K_BASE` 进行可复现的近似 token 计数，按最大 token 数硬限制分块，并优先选择段落、换行和句末边界。
- 创建版本时固化 tokenizer、最大 token 数和最大分块数；处理时要求快照字段完整且与当前处理配置一致，缺失或不匹配时明确失败并要求重建。
- 在 UTF-16 代码单元偏移上保证代理对不被拆开；保存字符数、token 估计、内容 SHA-256、章节和规范化文本起止偏移。
- 使用 `versionId + ":" + chunkIndex` 生成稳定分块 UUID，按 `(version_id, chunk_index)` 幂等写入 `document_chunk`，清理重新解析后多余的旧块。
- CHUNK 写入前重新校验任务阶段、owner、lease token、租约有效期、pending 指针和文档删除状态，并重算正文摘要；F07 的阶段边界在完成 CHUNK 并进入 `EMBED`，当前由 F08 处理器继续消费。
