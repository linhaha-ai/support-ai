## 已交付范围

| 范围 | 交付内容 |
| --- | --- |
| 身份目录 | `GET /api/admin/users`；仅 ADMIN 可调用，返回用户标识、用户名、展示名、角色和启用状态，不包含密码或密码摘要 |
| 成员管理 | `GET /api/knowledge-bases/{kbId}/members`、成员 PUT/DELETE；支持列表、幂等新增/改权和幂等撤权 |
| 数据访问 | `KbMemberMapper` 使用复合键显式 SQL；授权采用 PostgreSQL `ON CONFLICT`，保留首次 `created_at`，更新权限和最近授权人 |
| 统一授权 | `AccessPolicy` 提供 ADMIN、KB-R、KB-W 校验；WRITE 可通过读写校验，READ 只能通过读取校验 |
| 权限隔离 | ADMIN 管理能力不代替成员读取权；`owner_id` 不参与授权；普通数据接口对不存在、停用、无成员权统一返回 404 |
| 前端 | 管理页面支持账号选择、READ/WRITE、授权或改权、两步确认撤权、禁用账号不可选，以及加载、空、失败和重试状态 |
| OpenAPI | 四个新增接口均包含 operationId、Cookie 鉴权、路径/请求模型和写请求 CSRF 头描述；未添加重复的 `@ApiResponses` |

F04 没有新增表结构，继续复用 V5 的 `knowledge_base` 与 `kb_member`。成员复合主键操作使用显式 Mapper SQL，不使用不适合复合键的 `updateById` 或 `deleteById`。

当前成员列表按 F02 的小规模账号目录一次读取并在内存映射，避免逐成员查询；正式账号规模扩大或引入账号删除前，应改为按成员 ID 批量查询。`AccessPolicy` 的读取校验由 ACTIVE + 成员联合查询和成员详情查询组成，足以约束后续请求；F05 起的文档写入 SQL 仍须再次携带成员 WRITE 条件，不能仅依赖请求前检查来抵御极端并发撤权。
