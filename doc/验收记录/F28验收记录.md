## 实现范围

- `AssistantHistoryService` 从当前用户、当前会话中分页选择完整成功轮次，默认最多 3 轮；问题、回答、来源快照及来源说明预留字符合计不超过 6000。超出预算不截断轮次，可继续寻找较早的完整合法轮次。
- 检查每轮全部登记来源，包括模型使用但未在答案中引用的来源。任一文档版本不再 active、被删除、正文不可用或工具来源失去授权，整轮不进入历史；固定知识库范围失去权限时直接停止运行。没有独立摘要缓存或持久框架记忆可绕过这些检查。
- 历史数字引用转为本轮新来源句柄，相同根来源去重。继承记录直接保存 `origin_source_id=根来源ID` 和根来源的历史 `tool_call_id`，不指向上一轮副本，也不伪造本轮调用。
- 登记前锁定当前运行中的助手消息，SQL 验证本人会话、完整成功根轮次、递增序号、原始根记录、成功工具审计、当前成员权限及真实文档/工单，再从数据库复制快照。任一来源失败，独立短事务整批回滚；登记成功提交后才允许入模。
- 历史作为一条数据消息注入 ReactAgent，每次运行使用独立 run 标识；每次模型调用前和最终回答发送前复核全部登记来源，不只检查显式引用。
- 当前工单追问从显式编号或最近合法工单轮次确定目标。“现在呢”“它解决了吗”“上次那个工单解决了吗”等要求本轮查询；明确回顾先前状态可以使用原快照。多个候选或缺少合法上下文时明确提示补充编号。
- 服务端同时校验本轮调用过 `getTicketStatus`、答案引用的是目标工单的本轮直接来源。查询另一个工单、只引用继承来源或完全不调用工具均不能通过当前状态校验。
- ReactAgent 的模型/工具异常保留首次失败，阻断后续调用并在图返回后检查，避免框架将异常吸收为普通返回后形成成功答复。错误通过既有持久终态与 SSE 协议展示。
- 来源响应新增 `originSourceId`、`toolCallId`、`inherited`、`ticketQueriedAt` 的 OpenAPI 描述。工单卡片显示中文状态、“先前查询结果/本轮查询结果”和查询时刻；`isCurrent` 仅表示该回答本轮直接查询，不代表打开历史页面时状态仍然实时。
- 复用既有 `message_source`、`tool_call` 和会话/run 表，不新增迁移、接口入口、工具或业务写操作；RAG 继续使用既有编排。

## 场景核对

| 场景 | 已验证结果 |
| --- | --- |
| 三轮讨论同一工单 | 第一轮查询 OPEN；外部更新为 RESOLVED；第二轮询问先前结果仍显示 OPEN 且没有新调用；第三轮“现在呢”实际产生新的工具调用并返回 RESOLVED |
| 多轮根来源继承 | 第三轮继承仍直接指向第一轮根记录；历史调用 ID 保持原值，根来源去重，运行回查可返回继承标记 |
| 撤销知识库成员权 | 后续生成失败且不进入 Agent；历史内容变为不可读，来源响应和 run 查询均不返回工单快照 |
| 混合文档与工单 | 历史保留两类来源，即使答案只引用工单；文档不再 active 或逻辑删除时整轮历史被排除 |
| 跨用户/跨会话与批次回滚 | 其他用户不能读取根来源；同用户其他会话不能继承；合法根与非法根混合登记无残留记录 |
| 历史预算和来源闭包 | 超长整轮跳过；未引用来源失效也排除整轮；继承来源统一转换为新句柄 |
| 实际 ReactAgent 编排 | 用替代 ChatModel 驱动真实 Agent 执行工具后回答，两个模型请求各只包含一次历史；没有调用真实模型服务 |
| 权限或工具失败 | 入模前失效时模型不接收历史；工具失败或参数 JSON 无法解析均不产生成功答案和第二次模型调用；答复前失效不追加正文 |
| 当前状态伪装 | 没有工单调用、引用其他工单或用历史继承结果冒充本轮查询均失败 |
| 前端来源协议 | 拒绝缺少根来源、继承来源误标本轮状态、查询时间非法的响应；两种来源卡片显示正确 |

本次曾发现真实 ReactAgent 在节点异常时可能返回普通结果，已通过首次失败状态记录修正，并在模型权限失败及工具失败场景中验证；定向测试现全部通过。
