当前开发库已核对 Flyway V10 `create chat conversation` 成功登记；四张会话表、关键幂等/消息序号/run 角色/复合外键/请求哈希约束、`uq_chat_run_active_session` 部分唯一索引和 `chat_session` 中文表注释均存在。该开发库结构核对不替代空库 Testcontainers、生产 Mapper、真实业务 API 或浏览器交互验收。

## 已实现内容

- 新增 Flyway `V10__create_chat_conversation.sql`，创建 `chat_session`、`chat_session_kb`、`chat_run`、`chat_message` 四张表，并提供中文表列注释。
- `chat_session` 约束标题非空、会话模式和正消息序号；`chat_session_kb` 使用 `(session_id, kb_id)` 复合主键，固定会话知识库范围。
- `chat_run` 约束 `(session_id, client_request_id)` 幂等唯一键、请求哈希格式、配置/用量/指标 JSON 对象与终态时间；部分唯一索引限制每个会话同时只有一个 `QUEUED` 或 `RUNNING` 的 run。
- `chat_message` 约束会话内消息序号唯一、每个 run 的 USER/ASSISTANT 角色唯一、角色与状态组合，以及 `(session_id, run_id)` 对 `chat_run` 的复合外键。
- `ChatSessionService` 只允许当前登录用户创建非空且不重复的 RAG 知识库范围，写入默认标题“新会话”和范围关联。
- bootstrap 的 `controller.conversation.ChatSessionController` 仅公开 `POST /api/chat/sessions`，要求登录和 CSRF；请求为 `{ "kbIds": ["..."], "mode": "RAG" }`，成功返回 201 及会话标识、标题、模式、固定范围和时间。
- `ChatRunService` 已建立内部 run 准备能力：校验当前会话所有权和范围、创建请求哈希、处理同键重用/同键不同载荷冲突/单活跃 run 冲突，并落库一条用户消息和一条助手占位消息。F10 不提供消息提交 HTTP 接口，不调用检索、模型、SSE、来源或历史逻辑。
- `ChatRunConfigurationSnapshotFactory` 为每个新 run 固化不含凭据的 Chat provider/model、Embedding provider/model/1024 维、Prompt 版本、精确余弦 TopK 和 pgvector/cosine 索引参数；非法提供方、缺少模型或非 1024 维配置会在创建 run 前失败，不再只保存 `{ "mode": "RAG" }`。
- Vue 会话页仅加载当前用户可读知识库，支持选择一个或多个知识库、固定 RAG 模式、创建中状态、加载或创建失败重试和创建成功摘要；不包含提问、流式输出、取消、来源或历史功能。

## 权限与一致性设计

- 创建会话和准备 run 均在事务中调用 `KnowledgeScopeAccess.lockAllReadable`。
- 知识库标识先按 UUID 排序；查询以 `SELECT ... FOR UPDATE OF kb, member` 批量锁定知识库与成员行，并要求全部仍为 ACTIVE 且当前用户有成员关系。任何一个不满足时，整个创建或准备操作失败，不留下部分范围。
- 会话范围只从 `chat_session_kb` 读取，消息输入不能传入或扩大知识库范围。
- run 准备先锁定当前用户拥有的会话，随后重新锁定整个会话范围，覆盖会话创建后撤权、停用或删除授权的情况。
- V10 数据库约束与应用层条件更新共同防止重复 run、并发活动 run、重复消息序号和同一 run 的重复角色消息；用户/助手成对消息由 `ChatRunService` 在同一事务内创建，仍需以集成测试验证异常回滚场景。

## 复现与待执行命令

在仓库根目录、Docker 与本机开发环境就绪后，按以下顺序执行：

```powershell
mvn -f backend/pom.xml -DskipTests clean compile
mvn -f backend/pom.xml clean test
mvn -f backend/pom.xml -Pdb-it verify
npm --prefix frontend run test -- --run
npm --prefix frontend run build
```

还需启动应用和数据库，在已登录页面人工验证：选择一个或多个有 READ/WRITE 权限的 ACTIVE 知识库创建会话应返回 201；空范围、重复范围、无成员关系、停用知识库和撤权竞争均应失败且不写入部分数据；OpenAPI 只出现会话创建接口，不出现消息提交接口。

只有同时满足以下条件，才可在开发计划勾选 F10：

1. F09 前置依赖完成后端、数据库和场景验收。
2. 上述 Maven、Testcontainers、前端测试和构建命令均以实际报告成功结束；当前前端两项已满足，后端项仍待执行。
3. 空库 Flyway 能执行 V1—V10，V10 的四张表、约束、索引与中文注释均被核验。
4. 真实登录 API 和浏览器场景确认会话只属于当前用户、范围固定、授权撤销即时阻断后续 run 准备。
5. 并发与幂等场景确认同请求键只产生一个 run，同键不同内容和第二个活跃 run 返回冲突，且不产生孤立消息。
6. Ollama、DashScope 及混合角色运行分别核对配置快照，确保模型、Prompt、TopK、索引和 1024 维空间可追溯，且不包含 API Key、端点凭据或业务空间密钥。
