# F12 验收记录：生成有依据的回答并登记全部来源

日期：2026-09-21

结论：**功能代码、迁移和自动化测试代码已完成，尚未通过完整运行验收，开发计划保持未勾选。**

## 本阶段实现

- 新增 Flyway V11 `message_source`，保存助手消息、本轮引用编号、是否显式引用、知识库、文档 chunk、定位 JSON、生成时快照和历史来源指针。
- F12 只允许 `DOCUMENT` 来源；工单和工具表尚不存在，`TICKET` 来源字段及约束按后续工具任务迁移扩展。
- 新增 MessageSource PO、枚举、Mapper 和 Repository，JSONB 使用显式转换，来源按消息和引用编号稳定读取。
- run 增加 `QUEUED -> RUNNING -> COMPLETED/FAILED` 条件更新；领取时同时核对 run、会话、用户消息、助手消息和已持久化问题。助手消息只允许从同一 run 的 `STREAMING` 进入 `COMPLETED/FAILED`，空白答案不能完成。
- 授权检索后按候选 chunk 再次校验当前账号、会话所有权、RAG 模式、固定知识库范围、成员关系、ACTIVE 知识库、未删除文档、active READY 版本及当前 embedding 空间；复核不再次调用 EmbeddingModel。
- `PreparedChatRunResponse` 自包含会话标识和已持久化的规范化问题，`RagAnswerService` 不再接收可与 run 错配的独立会话/问题参数。
- `RagAnswerService` 为复核后的片段分配 `[1]`、`[2]` 等本轮编号；run 准备、来源登记、完成和失败边界均使用 `REQUIRES_NEW`，全部来源提交后才调用统一 `ChatClient`。
- 系统提示明确把文档正文视为不可信数据；正文只放在用户证据区，不作为 system 指令。
- 最终答案只将已登记且实际出现的编号标记为 `is_cited=true`；未知编号保留为普通文本，不创建可点击来源；未显式引用的入模证据继续保留。
- 无证据时不调用 ChatClient，保存“资料不足”回答并正常完成；模型异常或空白回答保存脱敏 FAILED 终态，不出现 COMPLETED 空答案。
- 新增 `GET /api/chunks/{chunkId}/source`。当前启用账号必须仍是 ACTIVE 知识库的 READ/WRITE 成员，且文档未删除、版本 READY、正文存在；历史 READY 版本允许预览并返回 `isCurrent=false`，但不会重新参与当前 RAG 检索。
- `support.ai.rag.top-k` 默认值为 6，可在服务端配置，客户端不能指定用户、知识库范围、提示词、模型端点或自由过滤条件。

## 事务与失败边界

```text
F10 在独立短事务准备并提交 QUEUED run 与成对消息
-> F11 会话授权检索
-> 按候选 chunk 再次复核
-> 复核 run/会话/成对消息/问题及会话固定知识库范围
-> RUNNING + 全部 message_source 在独立短事务中提交
-> 事务外调用 ChatClient
-> 助手正文 + 合法引用标记 + COMPLETED 在短事务中提交
```

无证据分支不创建来源，也不调用 ChatClient；它将 run 置为 RUNNING 后在同一短事务保存非空资料不足回答并完成。检索、序列化、持久化、模型异常和模型空响应均不会写成成功完成；数据库只保存稳定错误码和脱敏说明，不保存供应商原始报文或凭据。

## 待执行验收

按项目规则，本轮没有擅自运行 Maven、Docker、Flyway 或真实模型。先执行：

```powershell
mvn -f backend/pom.xml -DskipTests clean compile
mvn -f backend/pom.xml clean test
mvn -f backend/pom.xml dependency:tree
mvn -f backend/pom.xml -Pdb-it verify
```

随后启动 PostgreSQL 与 Ollama，准备 `qwen2.5:3b`、`bge-m3`，启动应用并确认 Flyway 从 V10 升级到 V11。导入可回答资料并形成 READY active 向量后，以内部集成验收或 F13 入口执行首批 20 道题，重点确认：

1. ChatClient 调用开始前，数据库已经存在本轮全部入模来源。
2. 资料内回答的合法引用能通过来源接口定位到正确文档、版本、章节和正文。
3. 资料外问题正常完成为资料不足，不产生来源，不编造业务规则。
4. 未引用但入模的片段仍在 `message_source`，未知编号不生成可点击来源。
5. 检索后撤权或版本失效的候选不能进入模型；历史 READY 来源只能预览并显示 `isCurrent=false`。
6. 无成员管理员、跨用户、停用账号、停用知识库和删除文档均不能预览来源。
7. 模型异常和空响应使 run/assistant 进入 FAILED，不出现完成的空回答，错误不泄露供应商详情。

DashScope 场景需另行注入北京地域凭据，并确认 chat 与 embedding 角色使用预期的提供方、模型和 1024 维空间。
