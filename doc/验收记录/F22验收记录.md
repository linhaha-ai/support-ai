# F22 验收记录：错误码与接口名的关键词融合检索

日期：2026-09-23

结论：**F22 的精确关键词召回、统一授权双路查询、RRF 融合、配置追溯和同集比较工具已实现并通过定向自动化验证；同一开发集的真实 VECTOR/FUSION 对比尚未执行，因此 F22 保持未勾选，默认策略保持 `VECTOR`。**

## 本阶段实现

- 在 `AuthorizedRetrievalRepository` 内新增 WRITE 知识库和可读会话两类关键词查询，与向量查询复用成员权限、启用账号、知识库状态、会话范围、当前 READY 版本、文档删除状态及 Embedding 提供方、模型、维度过滤。
- 对错误码、HTTP 方法与接口路径、CamelCase/下划线业务标识符及引号中的显式术语生成转义后的精确正则；错误码和接口路径带边界，`PAY-CB-1001` 不会把 `PAY-CB-10010` 当作关键词命中，查询基础接口也不会把更长的 `/close` 接口当作精确路径命中，同一路径的正确 HTTP 方法获得更高关键词分数。
- `FUSION` 策略按配置扩大向量和关键词候选，以稳定 `chunkId` 去重，使用 RRF 合并两路排名并采用确定性并列排序；没有明确关键词的自然语言问题只保留向量语义排序。
- 新增 `support.ai.retrieval.strategy`、`candidate-multiplier`、`rrf-k` 和 `max-keywords` 配置；默认策略明确为 `VECTOR`，未因隔离测试成功直接开启融合。
- WRITE 检索调试接口可为单次请求选择 `VECTOR` 或 `FUSION`，响应返回实际策略及两路候选数；检索证据分数说明区分余弦相似度与 RRF 分数，OpenAPI 注解已同步。
- `chat_run.config_snapshot` 升级为 `f22-v1`，记录实际检索策略、TopK、候选倍数、RRF 常数和关键词上限，继续保留 Chat、Embedding 和提示词配置且不写入密钥。
- 评测脚本新增 `compare` 命令，强制两次运行使用同一 development 数据集 SHA-256、Git 提交、环境及除策略外的相同配置；输出整体与分类召回变化、收益题、回退题、证据变化题、用量和 P50/P95 耗时差值。

## OpenAPI 基线复核

`OpenApiDocumentationTest` 可完成应用上下文启动，7 项中 5 项通过、2 项失败；两项均在本轮修改前已存在，其中完整文档失败已记录在 F20 验收记录：

- `/v3/api-docs` 因 Knife4j 与 SpringDoc 版本不兼容触发 `NoSuchMethodError: SpringDocConfigProperties.getGroupConfigs()`，早于具体 F22 Schema 断言。
- 未知检索字段由知识库异常处理器返回 `KNOWLEDGE_RETRIEVAL_INVALID`，现有测试仍断言通用 `INVALID_REQUEST`。

本阶段没有顺带调整依赖或既有错误码契约；F22 新增 DTO、枚举和 OpenAPI 注解已完成聚合编译，运行时文档仍需基线修复后复核。

- F22 依赖 F21；F21 因 F20 前置链路、语料实际 ID 绑定和本机模型/后端不可用，尚无可比较的真实纯向量基础结果。
- 尚未证明错误码和接口名在完整开发集上的净收益，也未逐题复核融合对中文自然语言、资料不足、权限和版本题的回退。
- 尚未取得两种策略的真实检索、生成、总耗时和模型用量，不能决定默认策略或候选参数。
- 认证后的 OpenAPI JSON 基线仍失败，运行时接口文档需在依赖兼容问题修复后复核。

## 完成判定

只有 F21 真实基础结果可用，并在同一 60 题开发集上完成纯向量与融合双跑、人工核对收益与回退、记录成本变化且确认权限边界后，才可勾选 F22。当前结论是“融合检索独立能力与比较工具实现完成，真实质量验收待前置和环境”。
