# F17 验收记录：追问改写与检索问题补全

日期：2026-09-22

结论：**F17 的代码、测试用例和文档契约已落位；本轮未运行 Maven、数据库、真实模型、API 或浏览器验收，开发计划保持未勾选。**

## 实现范围

- 追问改写只接收 F16 已按当前用户、会话、成员权限、文档及 active/READY 版本校验后的完整历史，不读取客户端提交的历史或范围参数。
- 无历史、改写关闭、完整问题不含上下文指代，或问题已提供错误码、HTTP 状态、通用 API 路径和异常类时直接使用原问题，不产生额外模型调用；“怎么办”等独立短追问仍可结合历史补全。
- 需要补全的追问通过非流式 Chat 调用改写，历史与当前问题均标记为不可信数据；模型只能返回单字段 `{"query":"完整检索问题"}` JSON。
- 空白、非法 JSON、额外字段、控制字符、超过 500 字符或模型异常时，稳定回退到原问题，改写失败不改变问答终态语义。
- 改写结果只作为 `retrieveReadableWithinSession` 的 query；用户标识、会话标识、固定知识库范围和 TopK 始终使用服务端可信参数。
- 用户消息、请求哈希和最终回答 Prompt 保留原问题。原问题、实际检索问题与改写状态保存到 run metrics，当前知识范围不可读时状态接口和 SSE `done` 事件均隐藏两段文本，权限复核异常同样失败关闭。
- 配置快照记录改写开关、`retrieval-query-json-v1` Prompt 版本和最大字符数。F17 复用 V10/V11，不新增 Flyway、HTTP/SSE 接口或前端改动。

## 关键边界

```text
加载 F16 已验证的有限历史
  → 判断是否存在上下文指代及明确检索标识
  → 无需改写时直接使用原问题
  → 需要改写时执行独立非流式 Chat 调用
  → 严格解析单字段 JSON，失败则回退原问题
  → 使用服务端 userId、sessionId 和实际检索问题执行授权检索
  → 最终回答 Prompt 继续使用原问题和 F16 历史
  → 将原问题、实际检索问题和状态写入终态 metrics
```

改写文本不具备身份、范围、过滤器或工具权限语义；即使历史包含提示注入内容，最终检索仍受既有会话授权 SQL 约束。

## 静态核对

以下检查仅确认实现与测试契约存在，不等同于运行通过：

| 场景 | 核对内容 | 预期结果 |
| --- | --- | --- |
| 无历史 | 改写服务输入空历史 | 不调用改写模型，使用原问题，状态为 `NO_HISTORY` |
| 明确问题 | 错误码、HTTP 状态、通用 API 路径、异常类或不含指代的完整问题 | 不调用改写模型，状态为 `SELF_CONTAINED` |
| 普通追问 | “这个错误怎么解决”等指代问题 | 严格解析单字段 JSON，实际检索使用补全问题 |
| 失败回退 | 模型异常、空白、非法、额外字段、控制字符或超长输出 | 问答继续使用原问题，状态为 `FALLBACK` |
| 调用隔离 | RAG 编排测试 | 改写问题只进入检索，最终回答 Prompt 仍包含原问题 |
| 会话隔离 | 两组不同历史 Prompt | 每次只包含调用方传入的已验证会话历史 |
| 提示注入 | 历史中包含角色变更或扩权指令 | 指令只位于不可信用户数据区，不进入系统规则 |
| 诊断脱敏 | 会话固定知识范围撤权后的 run 查询和 SSE `done` | 保留改写状态，隐藏原问题和实际检索问题；复核异常时失败关闭 |
