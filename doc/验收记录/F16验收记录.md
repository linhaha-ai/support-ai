# F16 验收记录：有限多轮对话及证据继承

日期：2026-09-22

结论：**F16 的代码、测试用例和文档契约已落位；本轮未运行 Maven、数据库、真实模型、API 或浏览器验收，开发计划保持未勾选。**

## 实现范围

- 从当前会话的业务消息库向前选择完整问答轮次，只接收 run、用户消息和助手消息均已成功完成的记录；失败、取消和不完整轮次不会进入历史。
- 默认分页选择最多 3 轮，并以 6000 字符限制历史总量。历史按原顺序整轮加入，不截断单条消息，超出预算的轮次不进入模型；最新一页均无效时继续查找更早候选。
- 每个候选轮次的全部来源都按当前账号、知识库、成员权限、文档、active/READY 版本和分块状态重新验证；任一来源失效即排除整轮，不能只保留答案摘要或部分来源。
- 历史只在业务 Prompt 中注入一次，不同时启用框架记忆或第二条历史注入路径，避免同一上下文重复计费和重复影响回答。
- 当前检索来源与历史继承来源在本轮统一编号；历史答案中的有效引用随本轮编号映射，同一分块的不同根来源不会合并丢失，未被历史答案显式引用但实际进入过模型的来源仍会传播和登记。
- 继承来源复制根来源的定位与快照，`origin_source_id` 始终直接指向根记录；根记录自身不再指向其他来源，避免多级链和循环继承。
- 来源批量登记提交后、Prompt 组装与模型调用前，按会话范围再次批量复核当前权限、active 版本和向量空间；复核失败不调用模型。
- F16 复用 V10 的会话、run、消息结构和 V11 的 `message_source`，不新增 Flyway 迁移，不改变现有 HTTP/SSE 接口，也不要求前端改动。

## 关键边界

```text
读取当前会话最近的完整成功轮次
  → 分页按当前授权与 active 版本校验该轮全部来源
  → 任一来源无效则排除整轮
  → 按最多 3 轮和 6000 字符预算保留完整轮次
  → 将历史与当前问题组成唯一业务 Prompt
  → 当前来源和继承根来源统一编号并在模型调用前登记
  → 登记提交后紧邻模型调用再次批量复核
  → 流式生成、校验引用并保存终态
```

该边界不包含 F17 的追问改写。F16 只决定可用历史和证据传播，检索问题仍使用用户本轮原始问题。

## 静态核对

以下检查只用于确认实现契约存在，不等同于运行通过：

| 场景 | 核对内容 | 预期结果 |
| --- | --- | --- |
| 历史预算 | 历史配置与选择服务 | 默认最多 3 轮、6000 字符，只保留完整成功轮次 |
| 来源有效性 | 历史来源查询与授权复核 | 任一来源失效时整轮排除，失效正文不进入 Prompt |
| 撤权竞态 | 来源登记后的紧邻批量复核 | 复核失败时不组装 Prompt、不调用模型并保存失败终态 |
| 根来源继承 | 来源查询、编号与保存逻辑 | `origin_source_id` 直接指向根记录，不产生继承链或循环 |
| 单次注入 | Prompt 组装与 ChatClient 调用 | 历史仅出现于一个业务 Prompt 区块，没有框架记忆重复注入 |
| 迁移和接口边界 | V10/V11、Controller 与前端差异 | 不新增迁移、HTTP/SSE 接口或前端改动 |
