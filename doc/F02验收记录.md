## 实现范围

- Flyway V2 创建 `app_user`，约束规范化唯一用户名、`ADMIN/USER` 角色和启用状态；迁移不包含账号密码。
- 使用 MyBatis-Plus 3.5.17 的 Spring Boot 3 专用 Starter、Sa-Token 1.46.0 和 jBCrypt 完成数据库认证。独立 SQL 保存默认演示账号 `admin/admin`、`support1/support1`、`support2/support2` 及兼容 jBCrypt 的 cost 12 BCrypt 摘要；手动执行时仅补齐缺失账号，不覆盖已有密码、角色或启用状态。
- 提供 `GET /api/auth/csrf`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`，统一返回业务码和 `traceId`。
- 使用 Sa-Token HttpOnly Cookie 保存登录凭据，并用独立 Servlet Session 保存 CSRF；登录成功签发新 token、轮换 Session ID 并换发 CSRF，同一浏览器再次登录会注销旧 token，退出同时失效当前 Sa-Token 和 CSRF Session。已登录账号被停用或删除时立即注销当前 token 并返回 401。
- 使用 Sa-Token Servlet 全局过滤器保护全部非公开路径，避免 Actuator 独立处理映射绕过 MVC 拦截器；过滤器内统一输出带 `traceId` 的 401/403 JSON。
- Sa-Token 只保存稳定用户 ID，密码摘要不进入登录会话；登录 DTO 的文本表示固定脱敏，接口响应不包含密码、密码摘要或 token 字段。
- 集成 springdoc-openapi 2.9.1 与 Knife4j 4.5.0，四个认证接口保留操作、请求参数、安全方案和数据模型注解，并显式输出 OpenAPI 3.0。成功响应由方法返回类型和 HTTP 状态注解生成，退出接口声明 204；不再逐接口重复声明响应列表。通用错误结构及实际 401/403 行为由统一错误处理和安全回归保证。Knife4j 的旧 springdoc 传递依赖已排除，文档页面、OpenAPI JSON 和 Actuator 文档分组继续受 Sa-Token 保护。
- Vue 页面支持身份恢复、登录、退出、认证错误重试，以及登录后的后端健康状态展示。
- 多模块组织中，data 维护 MyBatis-Plus 与数据库设施，`AppUser` 归 `com.haha.supportai.data.identity.entity.po`，`UserRoleEnum` 归 `.data.identity.enums`，`AppUserRepository` 和 `AppUserMapper` 分别归 `.data.identity.repository` 与 `.data.identity.mapper`；data 不依赖 identity。所有 Controller 集中在 bootstrap，当前 `AuthController` 位于 `com.haha.supportai.controller.identity`。identity 保留 `service / entity.dto / entity.vo / security / filter / exception / handler / config`：`AuthenticatedUser` 是内部认证快照 DTO，登录请求归 DTO，当前用户和 CSRF 响应归 VO；账号有效性检查、密码校验归 security。Java 演示初始化逻辑已移除。Cookie OpenAPI 安全方案、安全过滤器与身份异常处理器继续归 identity，公共响应和兜底异常分别归 common.entity.vo 与 common.handler，全局接口文档装配归 bootstrap。V2 表结构迁移内容与顺序保持不变，脚本随其他生产迁移集中于 bootstrap。本次数据访问迁移未执行 Maven，验收状态不变。
- AppUserRepository 保留 `findByUsername`、`findById`、`isEnabled` 三个查询方法，内部改用继承 BaseMapper 的 AppUserMapper。PO 显式映射表、列及 UUID 主键（INPUT），角色按字符串保存、时间使用 OffsetDateTime；MybatisPlusConfiguration 注册 UuidTypeHandler。当前查询无需自定义 XML。业务代码不再直接调用 JdbcTemplate/RowMapper，独立 SQL 验收夹具仍允许使用 JDBC，数据库映射及回滚测试待运行。

## 配置边界

演示账号脚本位于 `backend/support-ai-data/src/main/resources/db/seed/identity/init_app_user.sql`，不在 Flyway 扫描目录，也不由应用自动执行；运行时 Java 初始化及其配置开关已移除。应用可在空账号表下启动，先由 Flyway 创建表结构，再按 README 中的 PowerShell 命令手动导入。脚本使用 `ON CONFLICT (username) DO NOTHING`，不会覆盖已有账号的密码、角色或启用状态。本轮仅生成保存脚本，未在用户数据库执行。

普通开发配置继续在 YAML 中使用直接默认值，不使用带默认表达式的环境变量占位。DashScope 密钥仍只从启动进程环境变量注入；原生 Maven/Java 不会自动读取 `.env`。
